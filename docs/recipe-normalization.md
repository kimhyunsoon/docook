# 레시피 정규화 규칙

사용자가 글로 쓴 레시피를 docook 데이터로 옮길 때의 **단일 기준 문서**. 레시피 등록 요청을 받은 Claude 세션은 작업 전에 반드시 이 문서를 전부 읽고 따른다. 규칙에 없는 애매한 경우를 만나면 사용자에게 묻고, 정한 내용을 맨 아래 [결정 기록](#결정-기록)에 추가한 뒤 등록한다. 다음 세션이 같은 판단을 하게 하기 위해서다.

고정 어휘(분류·단위·조리 동작)의 실제 값은 항상 `GET /api/vocab`에서 확인한다. 이 문서의 예시는 설명용이고 어휘의 원본은 `backend/src/vocab.ts`다.

## 사용자에 대해

- 요리를 매우 잘하고, 양은 그때그때 조절한다. 조미료·간장 등은 계량 없이 "그냥 붓는" 경우가 많다.
- 따라서 레시피의 핵심은 **무엇을 넣는지와 순서**이고, 양은 사용자가 정확한 수치를 쓴 경우에만 의미가 있다.

## 기본 원칙

1. **원문에 없는 내용을 만들지 않는다.** 양·시간·불 세기·단계·재료를 추측해서 넣지 않는다. 일반적인 레시피 상식으로 빈칸을 채우지 않는다.
2. **같은 것은 항상 같은 말로.** 재료는 마스터의 표준명, 단위·조리 동작·분류는 고정 어휘만 쓴다.
3. **등록 전에 미리보기를 보여주고 확인받는다.** 해석이 갈린 부분은 미리보기에서 따로 짚는다.

## 요리

| 필드 | 규칙 |
|---|---|
| `name` | 사용자가 부르는 이름 그대로. 띄어쓰기는 표준 맞춤법으로 정리 (예: `김치찌개`, `대파 계란볶음밥`). 이미 같은 이름이 있으면 409 → 같은 요리인지 사용자에게 확인 후 `PUT`으로 수정 |
| `category` | 고정 어휘 중 하나. 음식의 나라로 나눈다 (`한국`·`중국`·`일본`·`이탈리아` 등). 나라가 애매하거나 섞였으면 `퓨전` (예: 마파두부 `중국`, 리조또 `이탈리아`). 목록에 없는 나라는 사용자에게 묻고 어휘에 추가 |
| `servings` | 원문에 `n인분`(기준 인원)이 있을 때만 정수로. 없으면 생략 (앱에 표기 안 함) |
| `summary` | 원문에 요리 소개·특징이 있을 때만 한 줄. 없으면 생략 |

## 재료

### 표준명

- 재료는 `GET /api/ingredients`의 **표준명(name) 또는 별칭(aliases)** 으로 쓴다. 별칭으로 보내도 서버가 표준명으로 바꿔 저장한다.
- **손질 상태는 재료명이 아니라 `note`** 로: `다진 마늘` → 재료 `마늘` + note `다진`. `송송 썬 대파` → `대파` + note `송송 썬`.
- **판매 형태가 다른 별개 상품은 별개 재료**: `간장` ≠ `국간장`, `물엿` ≠ `올리고당`, `다진 돼지고기`(다짐육)는 `돼지고기`의 손질 상태가 아니라 별도 재료.
- 고기는 `부위`까지 표준명에 포함 (`돼지고기 목살`, `소고기 양지`). 원문이 부위 없이 "돼지고기"면 부위를 추측하지 말고 사용자에게 묻거나, 마스터에 `돼지고기`를 새로 만든다.
- 브랜드명은 쓰지 않는다 (`청정원 진간장` → `간장`). 단, 사용자가 특정 제품을 고집하는 맥락이면 `note`에 남긴다.
- **`소금`·`후추`·`물`은 재료 목록에 넣지 않는다** (항상 있다고 본다). 조리 순서 본문에는 원문대로 쓴다 (예: `두부를 소금물에 데친다.`).

### 새 재료

- 마스터에 없으면 서버가 400으로 알려준다. 기존 재료의 다른 표기인지 먼저 확인한다 → 그렇다면 기존 표준명을 쓰고, 다음을 위해 `PATCH /api/ingredients/:id {add_aliases:[...]}`로 별칭을 등록한다.
- 정말 새 재료면 그 재료 항목에 `category`(재료 분류)를 함께 보내 생성한다. 응답의 `created_ingredients`를 사용자에게 보고한다.
- 중복 재료를 발견하면 `POST /api/ingredients/:id/merge {into_id}`로 병합한다 (이름은 별칭으로 흡수됨). 병합은 사용자 확인 후.

### 양

- **정량일 때만** `amount` + `unit`. 둘은 항상 함께 쓰거나 함께 생략한다.
- **비정량 표현은 양을 생략한다.** `약간`, `조금`, `적당량`, `적당히`, `기호에 맞게`, `간 맞춰`, `넉넉히`, `한 바퀴 둘러`, `그냥 붓는다` 등 → `amount`/`unit` 없이 재료만. note에도 이런 말을 옮기지 않는다.
- 숫자는 소수로: `1/2` → `0.5`, `반 개` → `0.5` + `개`, `한 큰술` → `1` + `큰술`. 앱도 소수 그대로 표시한다 (`2.5 큰술`, `0.5 개`).
- 단위는 고정 어휘로: `T`·`스푼`·`숟가락`·`밥숟가락` → `큰술`, `t`·`티스푼`·`찻숟가락` → `작은술`, `종이컵` → `컵`. 달걀은 `개`, 마늘은 `쪽`, 베이컨은 `줄`, 메추리알·방울토마토처럼 작은 알갱이는 `알`. 어휘에 없는 단위는 사용자에게 묻는다.
- 범위(`4~5개`)는 숫자 하나로 정한다 (큰 값). 양에 대한 부연설명(`큰 것 기준`, `작은 것은 1개` 등)은 note에 남기지 않는다.

### 묶음(section)·선택

- 원문이 재료를 묶어 쓴 경우만 `section`을 쓴다 (예: `양념장`, `소스`, `고명`). 묶음 없는 재료는 `section` 생략(=주재료).
- `있으면`, `생략 가능`, `선택` → `optional: true`.
- **대체 재료**(`A 혹은 B`, `A 대신 B`)는 A 바로 다음에 B를 넣고 B에 `alternative: true`. 앱에 `A 2개 / 혹은 B 5개`로 한 줄 묶음 표시된다. 같은 묶음(section) 안에서만, 조리 순서 본문에는 둘 다 쓴다.
- 순서는 원문에 나온 순서를 따른다.

## 조리 순서

- **한 단계 = 하나의 흐름.** 원문의 문장 단위를 기본으로 하되, 한 문장에 여러 동작이 섞여 있으면 자연스러운 곳에서 나눈다. 원문에 없는 단계는 만들지 않는다.
- **문체: `~한다` 평서형**, 짧고 담백하게. 예: `식용유에 대파를 볶아 파기름을 낸다.`
- 재료는 **표준명**으로 부른다 (원문이 `파`라고 했어도 `대파`).
- 불 세기는 `센불` / `중불` / `약불`. 원문에 있을 때만.
- 시간은 원문에 있을 때만 `minutes`(정수, 분)에 넣고 본문에도 `3분` 형태로 남긴다. `한소끔`, `노릇해질 때까지` 같은 표현은 본문에 그대로 두고 `minutes`는 생략.
- `method`: 그 단계의 **대표 동작 하나**를 고정 어휘에서 고른다. 애매하거나 여러 동작이 대등하면 생략한다.
- 양이 정량이 아닌 재료는 본문에서도 양을 말하지 않는다 (`간장을 둘러` O, `간장 1큰술을 넣고` X — 원문이 그렇게 쓰지 않았다면).
